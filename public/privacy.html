Privacy

Your library never leaves your computer

Snagly is local software. It runs a small server on this PC, stores its records next to the app, and sends nothing to the developer.

Last updated 27 November 2026

  • No account, no cloud, no analytics, no telemetry, no ads.
  • Snagly sets no cookies and has no login session.
  • Traffic goes only to YouTube/Google, and only for links you paste.
  • YouTube sign-in is optional and can be turned off at any time.

What stays on this computer

LocationContentsWhy
data/state.json Playlist and track titles, artist names, file paths, sizes, timestamps, status, settings Keeps the library across restarts and skips tracks already on disk
data/state.backup.json The previous state file Recovery if a save is interrupted
data/cache/ Playlist metadata, available format lists, and cached thumbnail images Avoids re-querying YouTube and lets cover art load without the browser contacting Google
Your save folder The downloaded audio/video files and their embedded tags That is the output you asked for
Browser localStorage Theme choice and whether you answered the sign-in prompt Remembers UI preferences
cookies.txt (optional) A cookie export you place in the Snagly folder yourself Fallback when the browser cookie database is locked
%TEMP% Short-lived files while tags are rewritten Deleted right after each write

data/ is plain JSON, not encrypted, and is excluded from Git. On NTFS, Snagly restricts the folder's Windows permissions to your account (plus SYSTEM and Administrators). Anyone who can sign in as your Windows user can still read it.

What leaves this computer

DestinationWhat is sentWhen
YouTube / Google The link you paste, your IP address, normal HTTP metadata, and — only with YouTube sign-in on — your YouTube cookies When you preview or download
YouTube image hosts A normal image request from the local Snagly server, including your IP address. Your browser never contacts these hosts directly. When thumbnails or cover art are shown, then from the local cache
GitHub A normal web request Only if you click a repository link

Nothing is sent to the developer: no usage data, no crash reports, no identifiers.

Cookies and browser sign-in

Snagly does not set cookies. There is no Set-Cookie header, no account, and no server-side session.

The Use YouTube sign-in toggle is different. YouTube often asks for a "confirm you're not a bot" check. To get past it, the local yt-dlp tool can read the YouTube cookies already saved in your Chrome, Edge or Firefox profile. Those cookies:

  • are read on this computer, by yt-dlp;
  • are used only for YouTube requests;
  • are never written into data/state.json or exported history;
  • are never sent to the developer or any party other than Google.

Snagly asks once on first visit whether to enable this. It stays off until you say yes. You can change it at any time in the composer footer. If the browser cookie database is locked, the download continues without cookies and Snagly tells you.

As an alternative, export a Netscape-format cookies.txt with a browser extension and save it beside server.js. Snagly uses that file instead of the browser database, which avoids the lock. The file contains your YouTube credentials: it is gitignored, never uploaded, and you should delete it when you no longer need it.

No tracking

Snagly contains no analytics, advertising, crash reporting, fingerprinting, or third-party fonts and scripts. Inter is served from this app's own public/assets/fonts/ folder, and the Content-Security-Policy blocks everything else.

Third parties

  • YouTube / Google — source of the media and the recipient of your requests. Google's privacy policy applies to them.
  • yt-dlp and FFmpeg — local tools installed through winget. They run on this machine.
  • GitHub — only if you visit the repository.

Snagly is not affiliated with YouTube or Google.

Children's privacy

Snagly collects no personal information from anyone, including children, because it does not collect personal information at all.

Security

The server listens only on 127.0.0.1, validates Host and Origin, accepts only JSON request bodies, restricts links to YouTube, and limits file operations to your library folder. Thumbnails are fetched by the server from a short allow-list of YouTube image hosts with redirects disabled, so the browser only connects to this PC and a crafted thumbnail URL cannot reach your network.

Changes

If data handling changes, this page and the repository's PRIVACY.md are updated in the same commit. The date at the top reflects the current version.
