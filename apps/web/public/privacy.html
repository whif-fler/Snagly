Privacy

Your library stays under your control

Snagly runs locally on your computer by default. This page explains both the local app and the optional self-hosted cloud mode.

Last updated 27 November 2026

  • No account, no analytics, no telemetry, no ads.
  • Local mode stores everything on this computer and sets no cookies.
  • Cloud mode stores jobs and files on the server for a limited time.
  • Traffic goes only to YouTube/Google for links you paste.

Local mode

In local mode Snagly is software running on your computer. It listens on 127.0.0.1, stores records in data/, and writes media into the folder you choose. There is no Snagly account and no cloud service.

What stays on this computer

Location Contents Why
data/state.json Playlist and track titles, artists, file paths, sizes, timestamps, status, settings Keeps the library across restarts and skips existing tracks
data/cache/ Playlist metadata, format probes, thumbnail images Avoids repeat requests and keeps the browser off Google
Your save folder Downloaded media with embedded tags and art The output you asked for
Browser localStorage Theme and UI preferences Remembers UI preferences

data/ is plain JSON, not encrypted, and is excluded from Git. It is readable by your Windows account.

What leaves this computer

The only requests are to YouTube/Google for links you paste, plus cover art fetched by the local server from YouTube image hosts. Your browser only connects to this computer.

YouTube access is guest-only. Snagly never reads browser cookies or a cookies.txt export, and it never sends your Google credentials anywhere. Public videos work without an account; age-restricted, private, members-only and bot-checked videos may fail.

Export history creates a CSV only when you click the button. It contains full file paths, which can reveal your username and folder layout. Review it before sharing.

Cookies

Local mode sets no cookies and has no login session. Snagly is guest-only, so yt-dlp does not read your browser cookies or a cookies.txt file. Cloud mode uses only the snagly_sid session cookie described below.

Deleting local data

  • Close Snagly and delete data/ for history and settings.
  • Use Clear cache or delete data/cache/ for thumbnails.
  • Delete files in your save folder, or use the library's delete actions.
  • Clear site data for the local address to remove browser preferences.

Security

The local server listens only on 127.0.0.1, validates Host and Origin, accepts only JSON request bodies, restricts links to YouTube, and limits file operations to your library folder. Thumbnails are fetched by the server from a short allow-list of YouTube image hosts with redirects disabled.

Self-hosted cloud mode

Cloud mode is software that an operator runs on a server. It provides anonymous sessions, a per-user library and short-lived server-side storage so you can save finished files to your device. The operator can access the server and everything stored on it.

What the server stores

Location Contents Why
SQLite database Anonymous user ID, hashed session tokens, CSRF tokens, job and track metadata, settings, timestamps Queue, library, ownership and progress
Per-user media folders Downloaded audio/video files Processing and signed delivery to your browser
Thumbnail cache Cached cover images Avoids repeat fetches and keeps the browser off Google
Session cookie A random identifier in snagly_sid Keeps your library separate from other users
Browser storage Theme, saved-track flags, optional folder handle UI state and folder saving

The database stores only a hash of the session token. Download links are short-lived signed URLs; anyone who obtains one can use it until it expires, so treat those links as secrets. The server operator can read metadata, media files, logs and backups. If you are not the operator, ask them about access and retention.

Retention and deletion

  • Finished jobs and files expire after the configured retention period.
  • Remove deletes the server copy of a job immediately.
  • Sessions expire automatically; clearing site data removes your cookie.
  • The operator can delete the entire data volume; this is irreversible.
  • Backups may retain deleted data until the operator rotates them.

Cookies and YouTube

Cloud mode does not read personal browser cookies or a cookies.txt file. The only Snagly cookie is the snagly_sid session cookie, which is HttpOnly, SameSite=Lax and Secure when HTTPS is enabled. The server contacts YouTube and thumbnail hosts using its own IP address. Your personal YouTube sign-in is not used.

What leaves the server

Requests go to YouTube/Google for links you paste and to YouTube image hosts for cover art. Cloudflare (or your reverse proxy) and the hosting provider process normal network metadata such as IP addresses.

Security

Cloud mode validates Host and Origin, requires CSRF tokens on unsafe requests, isolates users by ID, signs download links, restricts thumbnails to YouTube image hosts, runs media tools without a shell, and applies rate and size limits. Do not treat an instance without an authentication layer as suitable for untrusted public users.

Third parties

  • YouTube / Google — source of the media and recipient of the requests. Google's privacy policy applies.
  • yt-dlp and FFmpeg — run locally or on the server.
  • Cloudflare — optional TLS/tunnel provider in cloud mode.

Snagly is not affiliated with YouTube or Google.

Children's privacy

Snagly does not knowingly collect personal information from anyone, including children. An operator who needs age controls must add them at the deployment layer.

Changes

If data handling changes, this page and the repository's PRIVACY.md are updated in the same commit. The date at the top reflects the current version.
